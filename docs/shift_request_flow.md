# シフト申請の状態フローと操作フロー

## 1. 目的

このドキュメントでは、メンバーが行うシフト申請の状態遷移と、各ロールでできる操作を整理する。

## 2. 状態一覧

シフト申請は、以下の状態を持つ。

- DRAFT: 下書き状態。申請者が編集・削除できる。
- SUBMITTED: 提出済み状態。管理者による承認・却下待ち。
- APPLIED: 承認済み状態。実際のシフト登録対象として扱われる。
- REJECTED: 却下済み状態。再提出前提の終了状態。

## 3. 状態遷移

```text
DRAFT
  └─ 提出 → SUBMITTED

SUBMITTED
  ├─ 承認 → APPLIED
  └─ 却下 → REJECTED
```

## 4. 操作フロー

### 4.1 申請者の操作

1. メンバーは申請フォームから勤務日と希望シフトを選択する。
2. 申請内容はまず DRAFT として登録される。
3. DRAFT の間は、申請内容の確認・修正・削除が可能。
4. 提出すると SUBMITTED になる。
5. 承認されると APPLIED、却下されると REJECTED になる。

### 4.2 管理者の操作

1. 管理者は SUBMITTED 状態の申請を確認できる。
2. 承認すると APPLIED に遷移する。
3. 却下すると REJECTED に遷移する。

## 5. 制約

- DRAFT の申請のみ、申請者が削除できる。
- DRAFT の申請のみ、申請者が更新できる。
- SUBMITTED の申請は、申請者による編集・削除はできない。
- 承認・却下は、MASTER または CHIEF の権限が必要。

## 6. 画面上の利用イメージ

- 申請フォーム画面では、申請済み一覧に各申請を表示する。
- 各項目の右側に、DRAFT の場合のみ「削除」ボタンを表示する。
- 申請の状態は一覧上で確認できる。
